# Gadgets

> For the detailed tutorial see [TUTORIAL.md](TUTORIAL.md) · 中文版: [docs/README.zh.md](docs/README.zh.md)

A collection of practical tools accumulated through day-to-day development, covering AI daily-report generation, paper discovery, performance benchmarking, blog automation, and document translation.

Each directory under `tools/` is an independent tool that can be used on its own. Shared infrastructure is consolidated in the `common/` package at the repository root (installed via `pip install -e .`), providing general-purpose capabilities such as LLM invocation, JSON parsing, disk caching, atomic writes, translation, and Hugo deployment. The development workflow (planning / execution / change tracking) and all Claude Code skills are provided by **ai-companion** — a separate repository (`git@github.com:TzJ2006/ai-companion.git`) checked out in the sibling directory `../ai-companion/`, wired into this repo via hooks.

This document is an **overview** covering all the tools; for each tool's step-by-step operations, configuration, data formats, and FAQ, see [TUTORIAL.md](TUTORIAL.md) and each tool's own source documentation.

## Per-Tool Overview

### Summarize — AI Conversation Daily/Weekly/Monthly Reports

Automatically reads your daily AI conversation records (Claude Code / Codex / Cursor Agent / ChatGPT / generic JSON) and calls an LLM API to generate structured daily, weekly, and monthly summaries. Multi-device workflow: export conversation logs on each device, aggregate them via cloud-drive sync or manual copy, and generate the final daily report; once enough daily reports have accumulated, you can go on to generate weekly reports and monthly trend summaries. Via [ccusage](https://github.com/ryoppippi/ccusage) 20.x's per-source namespaced commands (`ccusage claude`, `ccusage codex`, `ccusage gemini`…), it automatically discovers and tallies token usage and cost across all agent CLIs. There are four AI summarization backends, switched uniformly via `--api`: `ollama` (default — local Ollama, keyless, Qwen3.6-35B), `claude_cli` (reuses the Claude Code CLI login state, no API key needed), `anthropic`, `openai`.

```bash
python -m summarize daily export                                   # Phase 1: export all unexported dates
python -m summarize daily merge --sync-all                         # Phase 2: sync all dates and merge day by day
python -m summarize weekly generate --week 2026-W12 --deploy       # Weekly report + deploy
python -m summarize monthly generate --month 2026-02 --deploy      # Monthly report + deploy
python -m summarize auto --deploy                                  # One-click full pipeline: export → merge → weekly → monthly + deploy
```

> The legacy entry points `python tools/summarize/daily_summary.py ...` / `weekly_summary.py` / `monthly_summary.py` still work (backward-compatible re-export shims), but the new `python -m summarize` form above is recommended.

For detailed step-by-step instructions see [TUTORIAL.md — Summarize](TUTORIAL.md#summarize) and the source doc [tools/summarize/tutorial.md](tools/summarize/tutorial.md).

### Research — Paper Discovery and Researcher Analysis

A unified academic research toolkit that provides four major capabilities through a single CLI entry point, `tools/research/research_scout.py`:

- **Paper discovery**: searches papers from arXiv / bioRxiv / PubMed via a three-stage LLM pipeline (fast screening → deep evaluation → citation impact), generates a research weekly report, and deploys it to Hugo. Supports conference-paper search and author search.
- **Deep paper insight (`--insight`)**: downloads the full text of papers, has the LLM analyze their writing structure, publication strategy, and reusable core knowledge; automatically matches OpenReview to obtain review comments and analyze consensus and disputes; synthesizes a cross-paper research writing guide.
- **Researcher profiling**: fetches paper and citation data from ArXiv + Semantic Scholar, has the LLM generate a research-trajectory analysis, computes a tier score, and automatically discovers advisor–student relationships via homepage extraction + co-authorship patterns. Supports same-name disambiguation and reverse lookup.
- **Citation graph analysis**: forward-citation / backward-reference analysis based on the Semantic Scholar API, paired with LLM-driven impact interpretation.

```bash
python tools/research/research_scout.py report --project my-project        # Full pipeline: search → three-stage evaluation → report
python tools/research/research_scout.py ask "找 Pieter Abbeel 最近的机器人操作论文"  # Natural-language search (auto-routes source)
python tools/research/research_scout.py profile "Sergey Levine"             # Researcher profile
python tools/research/research_scout.py citations 2301.12597               # Citation graph (by arXiv ID / DOI)
python tools/research/research_scout.py deploy                              # Deploy reports to Hugo
```

All LLM features support switching the backend via `--api`: `ollama` (default — local Ollama, keyless, Qwen3.6-35B), `claude_cli` (no API key needed), `anthropic`, `openai`.

For detailed step-by-step instructions see [TUTORIAL.md — Research](TUTORIAL.md#research) and the source doc [tools/research/TUTORIAL.md](tools/research/TUTORIAL.md).

### Benchmark — Performance Benchmark Suite

A cross-platform CPU/GPU FLOPS benchmarking tool that measures floating-point performance uniformly across different hardware vendors and precision tiers. Supports NVIDIA (CUDA), Apple Silicon (MPS), and Intel (XPU) for actual GPU runs (OpenCL may appear in `--info` detection only), covering precisions such as FP64 / FP32 / FP16 / BF16 / FP8 (experimental). Measurement uses warm-up + formal measurement + statistical analysis (median, IQR outlier rejection), with explicit GPU synchronization to ensure accurate timing. Results accumulate to CSV in append mode (never overwriting, naturally supporting multi-hardware accumulation leaderboards), and an interactive HTML report and leaderboard with Plotly charts can be generated, with support for deploying to a Hugo website and submitting to a public leaderboard.

```bash
# Note: all commands require cd into tools/benchmark/ first
cd tools/benchmark
python -m benchmark.cli                # Run all benchmarks (results appended to CSV)
python -m benchmark.cli --cpu-only     # CPU only
python -m benchmark.cli --gpu-only     # GPU only
python -m benchmark.cli --report       # Run benchmarks + generate HTML report
python -m benchmark.cli --report --deploy  # Generate report + publish to Hugo /benchmark/
```

For detailed step-by-step instructions see [TUTORIAL.md — Benchmark](TUTORIAL.md#benchmark) and the source doc [tools/benchmark/tutorial.md](tools/benchmark/tutorial.md).

### Website — Hugo Blog

A Hugo static blog site ("TzJ's Net", PaperMod theme), deployed to GitHub Pages (`https://tzj2006.github.io/`). It has a built-in incremental image/video compression pipeline (compressing only media changed since `.last_build`: images go through pngquant, videos through HandBrakeCLI) and local-model bilingual translation (Ollama by default, with vLLM on Linux / transformers on Windows as fallbacks; the model `tencent/Hy-MT2-1.8B` is auto-downloaded on first run, not going through a cloud LLM API). Auto-generated content (daily/weekly/monthly reports, research reports, benchmark pages, images) is written by the deploy pipelines directly into `tools/website/content|static` (the single Hugo content root, files stamped with a `gadget_generated` marker; hand-written files without the marker are never overwritten), then translated, compressed, built, and pushed. `tools/website/public/` is a **separate** deployment repository (`tzj2006/tzj2006.github.io`), automatically committed + pushed by the build script — do not commit to it directly.

```bash
pip install -e ".[website]"                          # Install dependencies (incl. torch + transformers for translation)
cd tools/website && bash update.sh                   # macOS/Linux: incremental compress + Hugo build + push Pages
powershell -ExecutionPolicy Bypass -File tools/website/update.ps1  # Windows (script cds to its own dir)
cd tools/website && hugo server -D                   # Local preview (dev server, includes drafts)
```

For detailed step-by-step instructions see [TUTORIAL.md — Website](TUTORIAL.md#website) and the source doc [tools/website/CLAUDE.md](tools/website/CLAUDE.md).

### Translator — Gradio Document Translator

A Gradio document translator built on the `common` translation engine: a Google-Translate-style local translation web page that translates text and files (`.md` / `.txt` / `.pdf` / `.docx` / images) while preserving Markdown formatting (fragments such as code blocks, URLs, and Hugo shortcodes are protected). It runs local inference, not a cloud API: it reuses `common.engine.create_engine()` to automatically select a backend (`ollama` is auto-preferred when the model tag is pulled; `transformers` is the Windows fallback, `vllm` is preferred on Linux, `llamacpp` is the low-VRAM GGUF option), keeps the model resident in memory (warm), and lazily loads on demand when switching models. The default model is `tencent/Hy-MT2-1.8B` (GGUF variant `tencent/Hy-MT2-1.8B-GGUF`), auto-downloaded on first use, overridable via `GADGET_TRANSLATION_MODEL` or the in-GUI model management. The source language can be set to `auto` (detected by the text's CJK ratio); when the target is `auto`, it flips between zh↔en.

```bash
pip install -e ".[translator]"   # Install dependencies (gradio + GGUF translation stack)
python -m translator             # Launch Gradio GUI (opens in browser)
```

For detailed step-by-step instructions see [TUTORIAL.md — Translator](TUTORIAL.md#translator). For UI wiring see `tools/translator/app.py`, for translation and file logic see `tools/translator/core.py`, and for the shared engine see `common/engine.py` and `common/translation.py`.

## common / scripts / ai-companion

### common/ — Shared Infrastructure Package

The shared layer depended on by all tools, installed as a Python package via `pip install -e .`:

- LLM invocation (a unified two-tier API, supporting the four backends `ollama` (default) / `claude_cli` / `anthropic` / `openai`)
- JSON parsing and repair
- SHA-256 disk cache (namespaces + TTL)
- Atomic writes and content hashing
- Local-inference translation engine (Ollama / vLLM / transformers / GGUF) and bilingual content generation
- Cross-platform Hugo deployment

Change shared capabilities (LLM, cache, translation, Hugo deploy) here.

### scripts/ — Ops and Maintenance Scripts

- `sync.py` — centralized rclone data sync (push / pull / status / bootstrap / config, covering the summarize / website / research / benchmark / backups categories; also includes a special `dag` category for generating + deploying the DAG site). Run `python scripts/sync.py`; config is the `sync` section of the repo-root `config.json` (override path with `GADGET_CONFIG`).
- `onboard.py` — repository-level one-time machine onboarding: fill in one YAML sheet (`tokens/onboard.yaml`), run the script once, and it automatically completes SSH configuration, Claude/Codex CLI installation and authentication, pip extras and ai-companion installation, per-tool config, and rclone bootstrap.
- `smoke.sh` — read-only smoke net across all tools (`--help` / `--info` / imports; no LLM, network, or writes). Run `bash scripts/smoke.sh`.
- `serve_local_llm.sh` — create a summarize-tuned Ollama variant and print env (`eval "$(bash scripts/serve_local_llm.sh env)"`). Persistent knobs go in the repo-root `config.json` `summarize` section (override path with `GADGET_CONFIG`).
- Others: `language.py` (Hugo bilingual audit + summarize report rename), `profile_translation.py` (translation-engine GPU profiler).

### AI Companion — Separate Repository

**ai-companion** is a separate Node.js repository (`git@github.com:TzJ2006/ai-companion.git`), checked out in the sibling directory `../ai-companion/`, **not within this repo**. It records function-level code changes, generates tests and HTML reports, provides the `/idea`→`/ccplan`→`/ccedit` planning-execution pipeline, and hosts all Claude Code skills (methodology + domain). This repo wires into it via the hooks under `.claude/` and `.codex/`.

It is simultaneously packaged as a **standard Claude Code plugin** and an **equivalent Codex integration** — ready to use upon install, no build required (the change-tracking hook is a pre-built single-file artifact committed alongside the repo). All skills (methodology skills: ccplan planning, optimize optimization, cchypothesis debugging, repo-audit auditing, repo-tidy tidying; domain skills: summarize code overview, slurm-gpu cluster detection, nature-benchmark / NIPS-2025-paper paper-writing advisors) live in that repo; this repo no longer contains a `skills/` directory. For installation see `../ai-companion/scripts/install.ts`.

### New Server Onboarding

Two complementary paths:

- **Machine configuration for this repo** — `scripts/onboard.py`: after filling in `tokens/onboard.yaml`, run it once to configure SSH, Claude/Codex authentication, pip extras, per-tool config, and rclone bootstrap.
- **Server system-level installation** — the script that one-click installs the SSH public key, Claude Code, Codex, Superpowers, Ponytail, and AI Companion for an Ubuntu 22.04/24.04 server has, along with the platform, migrated to the **ai-companion** repo: `../ai-companion/scripts/onboard-server.sh`. After the repo split, `--companion-repo` is passed the ai-companion repo directly (`git@github.com:TzJ2006/ai-companion.git`), and `--companion-ref` is no longer needed. For usage see `bash ../ai-companion/scripts/onboard-server.sh --help`.

## Output Directory

All generated output is consolidated under the `outputs/` directory (already gitignored, auto-rebuildable):

```text
outputs/
├── logs/         # Intermediate artifacts (export logs, run logs)
├── reports/      # Final reports (Markdown, JSON, HTML)
├── cache/        # LLM cache, search cache
├── data/         # Structured data (CSV, JSON profiles)
├── images/       # Charts and generated images
└── backups/      # Force-overwrite backups (website-force, etc.)
```

Hugo site content is written directly into `tools/website/content|static` (there is no separate `outputs/site` staging tree).

## Environment Requirements

- Python 3.10+ (the conda environment `AI` is recommended, `conda activate AI`)
- Node.js 18+ (only the separate repo `../ai-companion/` needs it)
- For each tool's specific dependencies see the `requirements.txt` in the corresponding directory
- common package + summarize / research / benchmark / website extras: `pip install -e ".[all]"` (`all` does **not** include `translator`; install `pip install -e ".[translator]"` separately)
- The website/translation features use a local inference engine (Ollama by default; vLLM on Linux / transformers on Windows as fallbacks); the model `tencent/Hy-MT2-1.8B` is auto-downloaded on first run

## Notes

- GPU benchmarking automatically detects CUDA / Apple MPS / Intel XPU
- The `tokens/` directory holds API keys and the onboarding sheet; it is gitignored — never commit its contents
- All generated files are output to the `outputs/` directory, which is gitignored
- The LLM backends are switched uniformly via the `--api` parameter: `ollama` (default), `claude_cli`, `anthropic`, `openai` (or `GADGET_LLM_BACKEND` globally)
- The translation path uses a local inference engine selected by `GADGET_TRANSLATION_BACKEND`: `ollama` (default when the model is pulled, via the local Ollama server) → `llamacpp`/`vllm`/`transformers` (in-process), model `tencent/Hy-MT2-1.8B`
- Cross-device data sync uses `python scripts/sync.py push/pull` (requires rclone configuration)
- Never `git add` auto-generated content, rclone-synced data, build artifacts (`build/`, `gadget.egg-info/`), or the deployment/theme repos under `tools/website/`
- Tool settings live in the repo-root `config.json` (gitignored; copy from `config.example.json`). Override the path with `GADGET_CONFIG`.
